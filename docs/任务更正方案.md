# OpenHBX TASK1任务更正与协作方案

**版本**：V3.0

**日期**：2026-08-28

**状态**：设计文档重构；生产实现状态以专项HLD/LLD和实验artifact为准

**产品基线**：`OCP_HBF_0_7`

## 1. 更正后的任务目标

OpenHBX长期允许扩展不同高带宽存储产品，但TASK1只实现一个严格隔离的OCP HBF v0.7.0产品profile。本轮不要求实现HBM、LPDDR或hybrid bonding精细模型。

TASK1交付：

1. 通过单个YAML配置装配HBF模拟器；
2. 以Ramulator 2 `IMemorySystem`接收`Request`并通过原callback完成；
3. 实现HBF Host、地址、Base Die、PAL/TSV和NAND主路径；
4. 覆盖可从OCP HBF PDF确认的packet、status、register、DLU、mapping、replay和可靠性行为；
5. 对UCIe、AMBA和vendor参数缺口保留明确阻断标记；
6. 建立Docker+CMake+CTest下的分级验证和可重放证据。

文档中的`HLD/LLD`是High-Level Design和Low-Level Design。用户口语中的`HDL/LDL`均按软件工程文档`HLD/LLD`处理。

## 4. Agent协作角色

### 4.1 Architecture Lead

- 冻结TASK1范围、需求ID、公共类型和模块依赖；
- 维护`TASK1-整体设计方案.md`、README、文件索引和追踪矩阵；
- 评审状态owner、接口所有权、规范来源和跨文档一致性。

### 4.2 Configuration and System Agent

- 负责01和02；
- 核对Ramulator当前ABI；
- 保证配置装配与系统运行内核分离。

### 4.3 Host, Address and Controller Agent

- 负责03、04和05；
- 核对OCP Host/packet/status/register与A1/R1-R5；
- 保证Host ordering、地址状态和Controller动态状态各有唯一owner。

### 4.4 PAL, Media and Verification Agent

- 负责06、07和08；
- 明确PAL不是OCP术语，TSV状态归06，NAND状态归07；
- 建立production path和证据等级正确的验证设计。

```text
 01/02         03/04
    |           |

          v

          v

```

HLD先冻结边界和需求，LLD再定义文件、API和算法。LLD发现边界问题时必须回写HLD，不能在LLD中静默改变owner。

## 6. 冻结的跨模块契约

- `OpenHbxSystem::try_submit()`是所有driver的唯一系统准入入口；
- Ramulator `send(false)`和内部Busy/Backpressured均零副作用；
- Accepted请求精确一次terminal/callback；
- 02拥有唯一cycle、EventQueue和generation；
- 03拥有Host ordering和response gate；
- 04拥有HBF mapping、BlockSequence、replay和ZoneMap；
- 05拥有DLU、Bank cache、ECC和Host可见ControlPlane；
- 06拥有PAL route、TSV EAT、mapping、spare和repair；
- 07拥有NAND Page/Block/payload、Media EAT、BBT和raw reliability；
- 08只观察公开接口，不替代生产组件。

## 7. 文档与状态规则

所有文档必须遵循[`设计文档编写规范.md`](设计文档编写规范.md)。所有实验必须遵循[`实验与测试执行规范.md`](实验与测试执行规范.md)。

- 设计存在：`PLANNED`；
- 部分生产代码：`PARTIAL`；
- 生产代码完成但证据不足：`IMPLEMENTED`；
- 对应范围满足实验门禁：`VERIFIED`；
- 外部规范或vendor数据缺失：`EXTERNAL_DEPENDENCY`或`BLOCKED_SPEC`。

旧build、手工编译、fake pipeline或agent报告不能单独升级状态。

## 8. 评审门槛

1. 每个需求有来源、owner、设计落点和Test ID；
2. Host、Address、Controller、PAL和Media不复制可变状态；
3. Busy、Rejected、completion、reset和stale event路径完整；
4. issue与completion-time commit明确分离；
5. HBF正式profile不存在HBM/LPDDR或传统SSD语义；
6. 外部UCIe/AMBA/vendor缺口没有被设计假设掩盖；
7. HLD/LLD文件名、章节、接口和追踪矩阵一致；
8. 状态结论不超过实际实验覆盖范围。
